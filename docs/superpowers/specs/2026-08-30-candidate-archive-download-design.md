# 候选图片归档下载设计

## 目标

管理员可以下载服务器当前全部候选图片的稳定 CSV 清单，并在本地仅按该清单归档图片；这个流程不创建训练同步批次、不上传回执，也不修改服务器的审核或下载状态。

## 边界

- 管理 API 提供只读、仅管理员可访问的 UTF-8 CSV 下载端点。
- CSV 使用采集器现有 30 列 manifest 合同，覆盖启用和停用候选，并按鱼种、来源、候选 ID 稳定排序。
- 管理端“采集与导入”页面提供“导出全部候选 CSV”入口和本地归档命令说明。
- 采集器新增 `--download-manifest PATH` 模式。此模式不加载鱼种配置、不访问元数据来源，只下载清单中的图片。
- 本地归档会校验已有文件的 SHA-256；已验证文件跳过，缺失、损坏或失败行重试。
- 每处理 10 行持久化一次 CSV；成功后清空旧下载错误，失败时记录 HTTP 状态或异常类型。
- Wikimedia Commons 仅在归档模式下允许通过官方 API 获取缩略图作为回退；CSV 中的原始来源 URL 不被替换。
- 训练 `local_sync` 继续只处理已审核通过的 ADD/MOVE/REMOVE 任务，不提供全部候选下载，也不使用缩略图替代训练原图。
- `local_sync` 只增强最终网络错误诊断；现有有界重试、退避、`Retry-After` 和失败可续传语义保持不变。

## 安全与可恢复性

- 归档路径必须解析在 `--output-dir` 内；不信任 CSV 中的绝对路径或目录穿越。
- 下载先验证为可解码图片，再原子写入目标路径。
- CSV 导出是 GET 只读操作，不写审计、批次、回执或候选状态。
- 本地归档不调用服务器回执端点。

## 验收

1. 管理员获得 30 列、稳定排序且包含全部候选的 CSV；匿名和普通审核员不能下载。
2. 从该 CSV 运行归档模式时，不触发任何采集函数。
3. 第二次运行会跳过 SHA-256 正确的文件，仅重试失败、缺失或损坏项。
4. 中途退出最多丢失 9 行进度；再次运行可继续。
5. `local_sync` 的 404、429/503 最终失败信息包含 HTTP 状态，且仍不泄露带令牌 URL。
