## 1. 目标

把桌面目录 `C:\Users\86166\Desktop\SukaSeafood_CV_Dataset_Collector` 中仍有价值的候选图片采集能力纳入 `sukaSeafoodReview` 主仓库，并把鱼种维护、采集配置生成、Windows 本地采集和候选 CSV 导入连接成一条清晰流程。

本设计只覆盖实际使用方式：Mao 单人、单实例运行本地采集器。不会为多进程同时修改文件、精确断电窗口、跨目录恶意替换或运行中数据库升级增加复杂实现和测试。

## 2. 已确认的边界

- 中国境内轻量服务器不请求 Fish-Vista、iNaturalist、GBIF、Wikimedia Commons，也不下载、缓存或代理图片。
- 服务器只保存鱼种、候选元数据、外部 URL 和审核结果。
- 海外来源的元数据请求全部由 Mao 的 Windows 电脑发起。
- 线上多人审核继续使用 PostgreSQL；本地采集器不参与多人审核和训练原图增量同步。
- 训练原图仍由已有 `local_sync/` 工具在 Mao 电脑下载；候选采集器只生成待审核元数据 CSV。
- 旧的本地 `review_candidates.py` 不迁入主仓库，因为线上审核页面已经替代它。
- 旧目录中的 1,221 行 CSV、缩略图、图片、缓存和其他 `output/` 内容不保留。

## 4. 动态鱼种目录

首次部署的鱼种表为空，不再运行或保留“补齐 SF001–SF005”的默认 seed 行为。六个固定账号的初始化不受影响。

每个鱼种保留以下基础字段：

- 不可修改的安全代码；
- 中文名；
- 英文名；
- 学名；
- 排序；
- 启用状态。

后台提供可折叠的高级来源覆盖字段：

- iNaturalist taxon ID；
- GBIF taxon key；
- Wikimedia Commons category；
- Fish-Vista filter。

这些字段默认为空。正常情况下采集器根据学名自动解析；只有自动解析结果不正确或来源无法解析时，Mao 才填写覆盖值。

鱼种生命周期规则：

- 新类别创建新代码；
- 不再使用的类别停用而不是删除，历史候选和审核继续可查；
- 名称拼写错误可以编辑；
- 实际物种发生变化时，停用旧代码并创建新代码，不直接把已有类别改成另一个物种。

## 5. 采集配置

API 新增仅 Mao 可访问的采集配置下载接口。接口读取当前数据库快照，只导出启用鱼种，不包含账号、会话、数据库地址或其他秘密。

下载的 `species_config.json` 至少包含：

- 配置格式版本；
- 生成时间；
- 每个启用鱼种的基础字段；
- 可选的高级来源覆盖值。

配置中不得写“共五种”或依赖 SF001–SF005。没有启用鱼种时，接口返回明确的中文业务错误，页面引导 Mao 先前往鱼种管理。

## 6. 本地来源解析

采集器按配置中的任意数量鱼种循环运行：

- Fish-Vista：默认按学名精确匹配；存在覆盖值时使用覆盖值。
- iNaturalist：默认按学名查询并选择精确 taxon；存在 taxon ID 覆盖时直接使用。
- GBIF：默认按学名解析当前 taxon key；存在 key 覆盖时直接使用。
- Wikimedia Commons：默认使用 `Category:<学名>`；存在 category 覆盖时使用覆盖值。

某个鱼种的某个来源失败时，终端必须显示鱼种代码、来源和可执行的解决建议。其他鱼种和其他来源继续采集。`--resume` 合并到现有 `collector/output/candidates.csv`，保留已有行并跳过相同候选身份。

采集结果继续保留来源、作者、许可证、原始记录和图片 URL 等可追溯字段，并输出审核系统现有导入器可接受的 CSV 合同。采集器不把候选自动标记为训练可用。

## 7. 管理后台页面

管理后台原“导入”标签改名为“采集与导入”，保持后台标签数量和总体导航简洁。页面按顺序展示四步：

1. **管理鱼种**：显示当前启用鱼种及数量；提供“前往鱼种管理”。
2. **准备采集器**：提供“下载采集器 ZIP”“下载最新鱼种配置”、中文说明和可复制的 Windows PowerShell 命令。
3. **本地生成 CSV**：说明解压、安装依赖、替换配置、运行采集以及 `--resume` 补采方式；明确输出路径为 `collector/output/candidates.csv`。
4. **预检查并导入**：沿用现有 CSV 选择、预检查报告和 Mao 显式确认提交，不绕过已有重复、许可证、来源和 URL 校验。

首次使用下载完整采集器 ZIP。以后鱼种变化时只需下载最新 `species_config.json`，再重新生成或增量补采 CSV。

采集器 ZIP 是主仓库 `collector/` 的发布构件，不包含输出、缓存、服务器凭据或历史 CSV。后台页面下载小型 ZIP 和 JSON，不产生海外图片流量。

## 8. 正常操作流程

```text
Mao 登录管理后台
  → 新增、编辑、启用或停用鱼种
  → 在“采集与导入”下载采集器和当前配置
  → 在 Windows 本地运行采集器
  → 得到 collector/output/candidates.csv
  → 回到后台上传并预检查
  → Mao 确认导入
  → 六名成员在线审核
  → 审核通过的数据再由 local_sync 增量下载训练原图
```

鱼种变化后重复这一流程。精确重复候选由现有导入器跳过，新增候选进入共享待审核池。

## 9. 错误处理

- 无启用鱼种：不生成空配置，页面引导先新增鱼种。
- 学名无法解析：指出具体鱼种和来源，提示检查拼写或填写高级覆盖。
- 单一来源超时或限流：保留其他成功结果，提示稍后使用 `--resume`。
- CSV 有阻断问题：后台只显示预检查结果，不提交任何候选。
- CSV 只有重复行：正常报告跳过数量，不制造重复候选。

不实现浏览器直接启动本机 Python、服务器后台采集任务、服务器图片代理或复杂分布式任务队列。

## 10. 验证范围

实施只要求与真实使用直接相关的验证：

- 配置下载包含全部启用鱼种且排除停用鱼种；
- 空鱼种目录返回清楚错误；
- 可选来源覆盖字段正确往返；
- 采集器不依赖固定五种，能读取零以外的任意数量鱼种；
- 基础来源解析和单一来源失败继续行为正确；
- `--resume` 不重复加入相同候选；
- 新生成 CSV 能通过后台预检查并提交；
- 管理页面显示四步中文说明及下载入口；
- 采集器 ZIP 不含输出、缓存、凭据和旧 CSV；
- 旧桌面目录只在迁移文件、正常验证和 ZIP 构建全部成功后删除。

不新增多进程文件竞争、恶意文件替换、精确崩溃时序、运行中 schema 升级或其他极端恢复测试。
