# SukaSeafood 多人协作审核系统设计

日期：2026-08-26

状态：设计已确认，进入实施

## 1. 项目目标

把当前只能在一台电脑上运行的候选图片审核器，升级为供小组共同使用的线上审核系统。

系统需要满足：

- 6 名固定组员可以登录并参与审核；
- 所有人共用待审核池，但同一张图片不会同时给两个人审核；
- 审核操作立即写入数据库，不需要“保存”按钮；
- 普通成员可以查看并修改自己的审核历史；
- Mao 作为唯一管理员，可以查看进度、管理审核结果、候选图片和鱼种；
- Mao 可以在自己的 Windows 电脑上增量下载新审核通过的训练原图；
- 线上轻量服务器不代理、不缓存、不存储图片文件。

正式入口：

- https://findai.top/sukaseafood/review

旧页面处理：

- 删除 YGF 仓库和服务器部署目录中的旧 Ocean Project 页面与资源；
- 删除原有 /project 和 /project-assets 静态文件路由；
- Caddy 对 /project、/project/* 和 /project-assets/* 明确返回 HTTP 404，防止这些路径落入 YGF 前端兜底页面；
- FindAI/YGF 的其他网页和接口不受影响。

## 2. 已确认的产品规则

### 2.1 固定账号

系统只创建以下 6 个账号，不开放注册：

- Hassan
- Mao
- Xinhui
- Wahid
- Sharmaa
- Yiming

Mao 是唯一管理员，同时也可以参与审核；其他 5 人是普通审核员。

每个账号在部署时生成一个随机初始密码。首次登录必须修改密码。数据库只保存 Argon2id 密码哈希，不保存明文密码。

Mao 可以为普通成员重置临时密码。Mao 自己忘记密码时，通过服务器上的管理命令重置。

### 2.2 登录行为

登录页直接显示 6 个椭圆形姓名按钮，不使用下拉框。按钮以可换行网格排列：

- 未选择时保持统一尺寸和中性边框；
- 点击姓名后，该按钮通过 CSS transform 轻微放大，并显示高亮背景、加粗边框和选中标记；
- 放大效果不改变周围按钮布局；
- 选择姓名后输入密码并登录；
- 这组按钮按单选组实现，支持键盘焦点、方向键和空格键，不能只依赖颜色表达选中状态。

- 首次打开网页时需要登录；
- 正常刷新页面后保持登录；
- 主动退出、修改密码、账号被停用或会话过期后需要重新登录；
- 默认会话有效期为 12 小时。

### 2.3 权限

普通成员可以：

- 从共享待审核池取得下一张图片并审核；
- 查看总进度和每位成员的已完成数量；
- 查看和修改自己的审核历史；
- 在审核页面切换中文和英文。

Mao 可以：

- 使用普通审核功能；
- 查看所有成员和整个数据集的进度；
- 查看和修改任何人的审核结果；
- 修正候选图片对应的鱼种、来源、预览图地址或原图地址；
- 新增、修改、停用鱼种；
- 通过 CSV 增加更多候选图片；
- 重新开放已审核图片；
- 释放或转交长时间未提交的当前图片；
- 导出本地增量下载清单；
- 重置普通成员密码。

Mao 的后台管理页面固定使用中文。

### 2.4 不重复审核

系统不预先平均分配任务，也不给任何成员规定审核数量。6 名成员共用一个待审核池，谁上线都可以继续审核。

每名成员同一时间最多保留一张“当前图片”。打开审核页时：

1. 如果该成员已有一张尚未提交的当前图片，继续显示它；
2. 否则从共享池取得一张尚未审核、也没有被别人打开的图片；
3. 数据库给这张图片写入 current_reviewer_id；
4. 其他成员取得下一张时会自动跳过它。

这个标记只用于避免两个人同时看到同一张图片，不包含平均分配、数量配额、租约或心跳。

成员刷新或重新登录后继续自己的当前图片。如果成员长期不再处理，Mao 可以在后台把这张未提交图片释放回共享池。系统不自动按时间释放，避免组员看图或查来源时图片突然被别人取得。

数据库还会对 candidate_id 的当前审核结果设置唯一约束，防止重复提交产生两条当前结果。

### 2.5 不确定结果

UNSURE 仍然算一次已完成审核，不会自动交给第二个人。

Mao 可以在后台集中查看所有 UNSURE。如果需要别人再次确认，Mao 可以手动重新开放并指定新的审核人。这个例外操作必须记录到审计历史。

### 2.6 即时保存

页面没有“保存”按钮。

点击“保留 / 拒绝 / 不确定”后：

1. 页面立即向 API 提交；
2. 数据库写入成功后才显示下一张；
3. 保存期间禁用重复点击；
4. 网络失败时保留当前图片和选择，显示重试按钮；
5. 重试使用同一个幂等键，不会产生重复记录。

## 3. 总体架构

在现有 dianshu-prod 服务器上部署一个与 YGF 相互隔离的应用：

- React + TypeScript 审核网页；
- FastAPI 接口服务；
- 独立 PostgreSQL 数据库和数据卷；
- 复用现有 YGF Caddy 作为 HTTPS 入口；
- Mao 电脑上使用独立的 Windows 本地训练集同步工具。

SukaSeafood 不使用 YGF 的业务表，也不把审核逻辑合并进 YGF 后端。两者只共用服务器、Caddy 和一个用于反向代理的 Docker 网络。

数据流：

    组员浏览器
        |  登录、取得共享池下一张、提交审核、查看进度和历史
        v
    https://findai.top/sukaseafood/*
        |
        v
    YGF 现有 Caddy
        |---------------------------|
        v                           v
    审核网页容器                  审核 API 容器
                                     |
                                     v
                              独立 PostgreSQL

    外部预览图地址 -------------> 组员浏览器直接加载

    Mao 后台 -- 小型增量 CSV --> Mao 的 Windows 电脑
                                      |
                                      v
                               外部原图来源网站
                                      |
                                      v
                                 本地训练集
                                      |
                              小型下载结果回执
                                      |
                                      v
                                  审核 API

图片流量不会经过中国境内的轻量服务器。

## 4. 路径与 Caddy 规则

正式路径：

- /sukaseafood/review：登录和审核页面；
- /sukaseafood/review/history：个人审核历史；
- /sukaseafood/review/admin：Mao 的中文后台；
- /sukaseafood/api/v1：登录、审核、管理和同步接口。

根域名 findai.top 直接处理这些 SukaSeafood 路径，保证用户要求的地址保持为：

- https://findai.top/sukaseafood/review

根域名的其他路径继续沿用现有规则跳转到 www.findai.top。

www.findai.top 下的 SukaSeafood 路径跳转到根域名的正式地址，避免出现两套会话和重复入口。

根域名和 www 域名下的 /project、/project/*、/project-assets/* 都返回 404。旧静态文件和静态路由从仓库及服务器部署目录中删除。

Caddy 必须先匹配 SukaSeafood API 和网页，再进入现有 YGF admin-web 的兜底路由。

网页构建时使用 /sukaseafood/review/ 作为资源路径和前端路由基础路径。API 与网页保持同源，生产环境不需要开放宽泛的 CORS。

## 5. 登录与安全

### 5.1 密码

- 使用 Argon2id 哈希；
- 初始密码随机生成，不写入 Git；
- 首次登录强制修改；
- 修改或重置密码后，撤销该账号现有会话；
- 管理员看不到其他成员的现有密码。

### 5.2 会话

- 服务端生成随机会话令牌；
- 数据库只保存令牌哈希；
- 浏览器 Cookie 使用 Secure、HttpOnly 和 SameSite；
- Cookie 只作用于 /sukaseafood；
- 修改数据的请求还需要 CSRF 防护；
- 默认 12 小时过期；
- 主动退出会立即撤销会话。

### 5.3 登录保护

- 不提供注册接口；
- 按账号和客户端地址限制连续失败次数；
- 多次失败后短时间锁定；
- 错误提示不暴露账号是否被停用；
- 服务器密钥和数据库密码只放生产环境文件。

### 5.4 服务端权限

所有权限都由 API 检查，不能只依赖前端隐藏按钮。

- 普通成员一次只能取得并操作自己的当前图片；
- 所有成员可以读取不含审核内容的全组进度统计；
- 普通成员的历史查询只返回自己的记录；
- 管理接口必须验证 Mao 的管理员角色；
- 每次管理操作写入审计日志。

## 6. 数据结构

### 6.1 users

保存固定账号、显示名称、角色、密码哈希、是否必须修改密码、启用状态、登录失败状态和时间戳。

### 6.2 sessions

保存会话令牌哈希、用户、到期时间、撤销状态和时间戳。

### 6.3 species

保存稳定鱼种代码、中文名、英文名、学名、启用状态和排序。

已经被候选图片引用的鱼种只能停用，不能直接删除。鱼种代码不能重复使用。

### 6.4 candidates

保存：

- 稳定 candidate_id；
- current_reviewer_id 和 current_started_at，仅表示尚未提交的当前图片；
- 鱼种；
- 来源数据集和来源记录 ID；
- 来源详情页地址；
- preview_url；
- original_url；
- 作者、许可证、署名、地点、日期等元数据；
- 是否启用；
- 当前版本和时间戳。

来源数据集与来源记录 ID 组成唯一键。导入时也检查重复图片地址，但不会静默删除已有人工记录。

现有数据的地址规则：

- iNaturalist：preview_url 使用 large 图片，original_url 使用原始尺寸图片地址；
- Fish-Vista：original_url 使用可直接取得媒体文件的地址；
- GBIF：保留媒体 identifier 或原始媒体地址；
- Wikimedia Commons：original_url 使用原始文件地址；
- 如果某个来源没有单独预览图，preview_url 可以与 original_url 相同，由浏览器负责缩放显示。

### 6.5 reviews

每张候选图片最多有一条当前审核结果。

保存审核人、决定、拒绝原因、备注、版本和时间戳。

沿用现有数据含义：

- KEEP：status = APPROVED，whole_fish = YES，exact_species_verified = YES；
- REJECT：status = REJECTED，只按拒绝原因更新能够确定的字段，不推断无关字段；
- UNSURE：status = UNSURE，whole_fish = REVIEW，exact_species_verified = REVIEW。

### 6.6 review_revisions

审核历史只追加、不覆盖。

用户修改历史时，reviews 保存当前值，同时 review_revisions 写入修改前内容、修改后内容、操作者、时间和版本。

### 6.7 audit_events

记录：

- 审核修改；
- 候选图片修改；
- 鱼种修改；
- 重新开放；
- 释放或转交当前图片；
- 密码重置；
- CSV 导入；
- 本地同步回执。

每条记录包含操作者、时间、对象、修改前内容、修改后内容和必要的操作原因。

### 6.8 export_batches 与 export_items

用于记录本地训练集的增量同步：

- 批次创建人、鱼种筛选、创建时间、过期时间和状态；
- 候选图片及其审核版本；
- 操作类型 ADD、REMOVE 或 MOVE；
- 每项状态 pending、succeeded 或 failed；
- 成功后的本地相对路径和 SHA-256。

仅仅生成或下载 CSV 不代表图片已下载成功。只有本地工具返回成功回执后，数据库才把对应项目标记为 succeeded。

## 7. 共享待审核池

### 7.1 不预分任务

初始 1,221 条候选数据和以后新增的数据都直接进入共享待审核池，不提前分给任何人，也不设置个人目标数量。

谁有时间上线，谁就可以持续审核。

### 7.2 取得下一张

登录后，API 先查找当前用户是否已有尚未提交的当前图片；如果有就继续返回同一张。

如果没有，API 从共享池中选择一张尚未审核且 current_reviewer_id 为空的图片，并在同一次数据库操作中把 current_reviewer_id 写为当前用户。数据库条件和唯一规则保证同时上线的两个人取得不同图片。

鱼种和来源筛选用于决定从共享池取得哪一类图片，不形成个人配额。

### 7.3 中断与释放

刷新、关闭页面或重新登录不会更换当前图片。成员下次回来时继续审核它。

系统不使用自动超时、租约或心跳。Mao 可以在后台查看当前被谁打开但尚未提交的图片，并在确认后：

- 释放回共享池；
- 转交给另一名成员；
- 打开来源页面检查异常。

释放或转交必须填写原因并记录审计日志。

### 7.4 提交后

提交成功后，审核记录保存实际审核人，候选图片退出共享池，并清除 current_reviewer_id。当前成员再次请求时取得另一张可审核图片。

## 8. 审核页面

### 8.1 图片加载

浏览器直接加载 preview_url，服务器不代理、不下载、不缓存。

图片区域从设置地址开始显示加载转圈：

- load 成功后隐藏转圈并显示图片；
- error 后停止转圈；
- 显示“重新加载图片”；
- 显示“打开来源页面”；
- 显示“图片链接失效”。

选择“图片链接失效”时，记录结构化拒绝原因 IMAGE_URL_UNAVAILABLE。Mao 修正 preview_url 或 original_url 后，可以重新开放该图片。

网页安全策略允许加载 HTTPS 外部图片，但脚本和 API 仍限制为本站资源。

### 8.2 中英文

审核页面保留中英文切换，并确保以下内容全部本地化：

- 页面按钮；
- 审核状态；
- 来源名称；
- 拒绝原因；
- 加载和错误提示；
- 筛选项；
- 历史页面。

数据库始终保存稳定英文代码，显示层按语言翻译，避免历史数据因为切换语言而改变。

### 8.3 审核操作

保留现有快捷键和主要按钮：

- K：保留；
- R：拒绝；
- U：不确定；
- 左右方向键：在允许的历史或当前列表中导航。

点击“拒绝”时，拒绝原因直接显示为一组可换行的椭圆形按钮，不使用下拉框：

- 所有结构化拒绝原因都同时可见；
- 点击后，该原因按钮轻微放大并高亮；
- 选中状态包含文字或图标标记，不能只依赖颜色；
- 选择“其他”后显示备注输入框；
- 拒绝提交必须包含一个选中的原因；
- 这组按钮按单选组实现并支持键盘操作。

登录姓名和拒绝原因是本期明确改为椭圆按钮的两个位置。鱼种、来源、状态等筛选控件继续使用下拉框。

提交期间显示保存状态并禁用按钮。数据库确认成功后才进入下一张。

### 8.4 历史页面

普通成员可以按鱼种、来源、结果和日期筛选自己的历史，并修改自己的决定、拒绝原因和备注。

修改时检查版本。如果另一个标签页已经更新过同一记录，系统提示冲突并显示服务器上的最新值，不直接覆盖。

Mao 可以查看和修改所有人的历史。管理员修改必须填写原因。

### 8.5 全员可见的进度

审核页提供所有成员都能查看的进度面板，显示：

- 候选图片总数；
- 已审核、待审核和当前正在查看的数量；
- 总完成率；
- 每位成员已经完成的数量；
- 每位成员的保留、拒绝和不确定数量；
- 当日新增审核数量。

普通成员只能看到这些汇总数字，不能打开其他人的具体审核内容或历史。

## 9. Mao 的中文后台

### 9.1 审核进度

全员进度面板显示基础统计。Mao 的后台在此基础上增加管理视图：

- 按鱼种、来源和结果分类的统计。
- 按成员和日期筛选统计；
- 当前被哪位成员打开但尚未提交的图片；
- 释放或转交当前图片的操作；
- UNSURE 和图片链接失效的待处理列表。

### 9.2 候选图片管理

Mao 可以搜索并修改候选图片的：

- 所属鱼种；
- 来源元数据；
- preview_url；
- original_url；
- 启用状态。

修改已审核图片的所属鱼种时，系统要求二次确认和填写原因。旧审核记录保留，当前结果失效，图片重新进入待审核状态并由 Mao 指定审核人。

### 9.3 鱼种管理

Mao 可以新增、编辑、排序、启用和停用鱼种。

已被候选图片引用的鱼种不能硬删除。

### 9.4 候选图片导入

CSV 导入分为预检查和正式提交。

预检查显示：

- 新增数量；
- 完全重复记录；
- 可能重复的图片地址；
- 无效鱼种；
- 缺少预览图或原图地址；
- 无效许可证。

正式导入使用数据库事务，不能只成功一部分。导入后的新候选图进入共享待审核池，并记录审计日志。

## 10. 本地增量下载训练原图

### 10.1 为什么在本地下载

生产环境是中国境内的轻量服务器，不适合从多个境外来源下载并再次转发原图。

服务器只处理网页、API、小型 CSV 和小型回执。原图由 Mao 的电脑直接从来源站点下载，减少服务器流量、临时磁盘占用和跨境长任务失败。

### 10.2 后台导出增量 CSV

Mao 可以选择一个鱼种或全部鱼种，点击“导出新增审核通过图片 CSV”。

后台显示每个鱼种当前待同步的数量。

CSV 包含：

- 批次 ID；
- 只能提交本批次结果的短期回执令牌；
- 操作类型 ADD、REMOVE 或 MOVE；
- candidate_id 和审核版本；
- 鱼种代码；
- 目标本地相对路径；
- preview_url 和 original_url；
- 来源详情页；
- 作者、许可证、许可证地址和署名；
- MOVE 或 REMOVE 所需的旧相对路径。

只有当前状态为 APPROVED 的图片生成 ADD。

生成 CSV 不会把图片标记为已下载。回执之前再次点击时，返回现有未完成批次，避免不断生成重复批次。

### 10.3 Windows 本地同步工具

提供一个可双击启动的 Windows 小窗口，同时保留命令行模式。

用户选择：

- 后台下载的增量 CSV；
- 本地训练集根目录；
- 可选代理设置，默认读取系统环境配置。

工具执行：

1. 校验 CSV 和批次信息；
2. 读取本地同步索引；
3. 跳过本地已经成功处理的相同候选图片和审核版本；
4. 从 original_url 直接下载 ADD 原图；
5. 使用 .part 临时文件，支持中断后重新运行；
6. 按来源限速，并支持 Retry-After 和指数退避；
7. 验证下载内容确实是可解码图片；
8. 计算 SHA-256 和感知哈希；
9. 检查完全相同的文件；
10. 成功后原子移动到 images/{species_code}/{candidate_id}.{extension}；
11. MOVE 只移动已有文件，不重新下载相同原图；
12. REMOVE 把文件移动到可恢复的 _removed 目录，不永久删除；
13. 更新本地同步索引；
14. 向服务器提交很小的成功和失败回执。

如果回执上传失败，工具生成 download_receipt.json。Mao 可以稍后在后台手动上传。

只有真正下载并验证成功的 ADD 项目才会被服务器记为 succeeded。下载失败项目继续保持 pending，下次导出时仍然出现。

### 10.4 审核修改后的同步

- 新审核通过：ADD；
- 已经下载但后来改为拒绝或不确定：REMOVE；
- 已经下载但后来改了鱼种：MOVE；
- 只修改作者、许可证等元数据：更新清单，不重新下载图片字节。

每次本地同步都会生成操作日志和最新训练集清单。

## 13. 异常处理

- 预览图无法加载：停止转圈，允许重试、打开来源或标记链接失效；
- 保存超时：保留当前选择，使用相同幂等键重试；
- 同一账号多个标签页重复提交：数据库唯一约束和版本检查阻止重复当前结果；
- 历史编辑冲突：拒绝旧版本覆盖，显示最新记录；
- CSV 导入验证失败：不写入任何部分数据；
- 本地原图下载失败：保持待同步；
- 回执上传失败：保留本地 JSON 回执；
- 本地下载中断：依靠 .part 文件和本地索引继续；
- 数据库不可用：明确显示维护状态，不假装已经保存。
